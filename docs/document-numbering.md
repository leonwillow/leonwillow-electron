# 文书取号

维护日期：2026-10-13。

入口为 `/documents`，功能授权使用 `documents`。管理员可管理模板、年度序号及文书删除；获授权的普通人员可查看全部文书，只能修改本人取号的文书，不能删除文书或模板。页面和 API 都执行相应限制。

## 取号与填写

文书主导航图标与“案件”共用同一悬停菜单逻辑：未固定时悬停或键盘聚焦展开类型浮层，移入可继续搜索和选择；鼠标停在主导航图标间空白处保持已打开菜单，离开主导航和浮层后延迟收起。空白本身不打开菜单，移到其他主图标时按该入口切换。右方向键进入搜索框，Escape 关闭并返回图标。顶部固定按钮按用户保存偏好，宽窗口仅在文书区常驻并让出正文空间；窄窗口回到浮层。点击图标或页头的“选择文书类型”也可打开菜单。

选择类型后，右侧表格显示该类型全部文书。工具栏提供搜索、全部/本人筛选、年份、刷新与“新增文书”，分页位于底部。选择保留在 URL，刷新及浏览器前进/后退可恢复类型；再次点击当前类型会返回其表格。文书区内选择类型会收起未固定菜单。管理员通过类型栏的“管理文书模板”进入 `?view=templates`；停用但仍有记录的类型保留在“已停用 · 历史文书”分组。

点击“新增文书”后打开弹窗，表格和筛选保留。类型固定为当前选择，年份默认为当年。弹窗不设置操作页签：左侧展示取号年份与受询问人，其他模板字段和检索事项放在“补充文书内容（选填）”中，可折叠且保留填写内容。填写受询问人即可提交；没有受询问人等对象字段的模板使用“文书事项”。简要对象优先匹配受询问人、被询问人、纳税人、当事人、单位名称、对象等占位符。新记录的检索事项默认来自对象文字。

取号不要求填写模板的其他内容。右侧始终显示真实 Word 预览，初次打开自动生成空白草稿，输入后合并 350ms 更新，不要求点击预览；过期请求结果不覆盖最新输入。未保存的文号显示“待取号”，预览不消耗序号。取得文号后留在同一弹窗，预览显示正式号码，可以点击文号复制或继续补填；展开状态不重置。正式下载 Word 时才检查管理员设置的必填字段。已提供的日期、时间、字段名和文本长度始终校验，避免保存无效数据。号码、年份、归属和模板版本不能通过修改文书改变。

查看和编辑已有文书沿用同一弹窗，历史预览使用原号码和模板。保存或下载期间暂时阻止关闭；预览请求独立于表单操作，失败显示重试入口。桌面左右布局并独立滚动，窄窗口在同一弹窗内按表单、预览顺序上下排列。

序号按文书类型和年份独立递增，新年默认从 1 开始；管理员可设置下一序号以接续已有文号。例如前缀 `滇税三稽查`、年份 `2025`、序号 `43` 生成 `滇税三稽查〔2025〕43号`。序号调整只能向前，删除不会回收号码。不同类型可以使用相同前缀；唯一性按类型和年份保证，管理员应根据业务需要配置前缀。

服务端锁定类型行，在同一 PostgreSQL 事务内写入年度计数、记录和首次修订；并发取号不会重复。客户端为一次提交提供 requestId，响应丢失后同一内容的重试返回原记录，不再消耗序号。更新通过 revision 防止覆盖其他操作刚保存的内容。

## Word 模板

支持标准 `.docx`，最大 5MB。管理员导入时解析占位符：文号位置使用 `{文书号}`，其他位置使用 `{字段名}`。`{年份}`、`{序号}`、`{文书名称}` 是系统字段；普通占位符使用文字、数字或下划线，不支持表达式、循环、条件和模块标签。模板中的内容仅作为文书数据，不作为操作指令执行。

已将用户提供的“询问通知书模板.docx”转换为 [可导入的模板](./templates/inquiry-notice.docx)，只替换需要填写的文本位置，保留其版式、正文、字体及页面设置。原桌面文件不改动。系统内“导入询问通知书示例”和“下载示例”使用同一模板。字段包括机关名称、受询问人、询问日期、询问时间、询问地点、涉税事项、联系人员、联系电话、机关地址及签发日期。

管理员可设置字段显示名、输入类型、默认值及下载 Word 时的必填状态。机关名称、联系人等固定内容可以设置默认值以减少填写。日期使用 ISO 日期输入，生成时显示为中文年月日；时间输入为 24 小时格式，生成时显示中文时分。

每次模板设置或文件替换产生新版本，旧文书继续使用取号时的模板及字段。删除类型只阻止后续取号；已有文书仍可按原模板补填、预览和下载。文书及模板均标记删除，版本、修订、请求标识及使用过的序号继续保留。

生成采用 docxtemplater / PizZip，填写文字进行 XML 转义。上传前检查压缩文件规模，并拒绝宏、嵌入对象、外部关系、自动 Word 域等不支持内容。浏览器按需加载 docx-preview，在不允许脚本执行的独立 iframe 内显示真实生成字节，文书样式不影响应用。预览可适宽缩放，最终排版以下载后在 Word 中打开的文件为准。

## 实现与验证

数据库表位于 `packages/db/src/schema/documents.ts`，迁移新增 document_type、document_template、document_sequence、document_record、document_revision 五张表。模块 HTTP 边界在 `apps/server/src/modules/documents/index.ts`，事务与权限在 service.ts，模板校验和生成在 template.ts。Web 路由加载类型目录及可用模板；类型侧栏位于 `components/layout/document-type-sidebar.tsx`，作为工作台唯一二级菜单框的文书内容按授权显示。`document-navigation-provider.tsx` 管理目录和类型选择，悬停、展开及固定状态来自 `WorkspaceNavigationProvider`；固定偏好统一为 `workspace-menu:v1:<userId>`，旧文书偏好参与一次性合并，详见 [布局说明](./layout-migration.md)。`views/documents` 负责工作区及表单，`lib/documents.ts` 通过 Eden 调用。共享 API 客户端对 DOCX 响应使用 Blob，避免二进制文件被当作文字解析。

类型导航沿用现有资金案件侧栏的列表和共享尺寸，记录表格采用原 contacts/table 的工具栏、内部滚动和底部分页结构；模板管理复用原知识库 collection-dialog / collection-card 结构与共享 Base UI 控件，使用统一排版、工作区留白和语义颜色。没有引入另一套主题或控件尺寸。

API 集成测试使用独立随机 schema，覆盖并发、幂等、年度与类型独立、失败不占号、简要取号、部分修改、Word 必填校验、归属权限、版本冲突、模板替换和删除后的历史保留。模板测试覆盖跨 Word run 的占位符、XML 转义、排版保留和非法上传。文书模板及完整生成样例均已渲染为页面图检查中文、版式和分页。
