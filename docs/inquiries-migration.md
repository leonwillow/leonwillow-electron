# 笔录功能

创建及维护日期：2026-11-04。

## 入口与使用

主图标栏新增“笔录”（`/inquiries`）。二级菜单同时展示独立笔录和案件文件夹；点击文件夹只展开/折叠，内部逐份展示笔录，点击笔录直接进入编辑。文件夹不显示数量，重命名、归档、删除按钮在该行右侧悬停或键盘焦点时出现，触摸屏保持可用。展开的文件夹内可新建笔录，子目录每页最多 30 条。目录搜索覆盖文件夹名、独立笔录及文件夹内笔录的标题和被询问人，同时支持全部状态、草稿和已完成筛选；查询由服务端完成，不受展开状态或当前分页限制。文件夹名称命中时展示其中符合状态的笔录，其他情况只展示匹配的子笔录。筛选自动展开匹配的文件夹，允许手动折叠；清空筛选后恢复原展开状态。

文件夹展开状态由持续挂载的笔录导航上下文管理，浮窗关闭和模块切换不丢失；从 URL 进入案件时展开对应文件夹。创建请求按目标目录保留幂等 ID，文件夹折叠或浮窗关闭后重试不会重复创建；保存成功刷新目录标题，删除末页最后一条后回到有效页。已删除重复的案件笔录表格页和编辑器返回列表入口；右侧只显示选中的笔录编辑器或未选择引导。新建笔录直接打开编辑器，新建文件夹仅展开目录并保留当前编辑内容，两种创建操作均清空目录筛选以显示新项目。旧的仅含案件参数 URL 仍可展开目录，但不再展示表格。菜单复用共享工作台的固定、键盘和窄窗行为；固定时 hover/focus 不切换内容，点击或 Enter 激活导航才切换。右方向键进入当前菜单，Escape 退出浮层。案件与笔录选择保留在 URL，刷新可回到当前笔录。

编辑器提供基本情况、询问人、唯一记录人、被询问人及问答。常用询问人在二级菜单底部维护，选用后带入姓名和检查证号；之后修改目录不改变历史笔录中的人员快照。表单不再显示年龄输入区域，居民身份证年龄仍按询问开始日期自动计算并保留在预览、保存和 Word 中；无法计算时留空。关系默认值和选项统一使用“法定代表人”，历史“法人”值在编辑控件、预览和 Word 中映射为该称呼及勾选状态，修改基础字段时保存当前名称。“其他”关系需要填写说明。

问答支持上方/下方插入、末尾添加、拖动或按钮排序、删除、撤销和重做。编辑历史最多保留 100 个快照，相邻 400ms 内的输入合并。宽窗口显示基础信息、问答、文书预览三栏，两侧可收起；较窄窗口通过页签切换，内容在工作区内滚动。

## 保存、权限与数据

编辑后每 5 秒自动保存草稿，也可手动保存或使用 `⌘/Ctrl+S`。保存只确认已提交的快照，保存期间新增的输入仍属于未保存修改。页面内导航会等待保存并复核最新内容；失败时保留编辑器，并允许继续编辑或明确放弃修改后离开。刷新/关闭窗口对未保存内容触发浏览器离开保护。

完成笔录在服务端校验必填字段、有效且递增的起止时间、至少两名询问人、每人的姓名与检查证号、唯一记录人以及“其他”关系说明。草稿允许逐步填写。完成后继续修改会重新成为草稿；完成校验失败不会被同一快照的自动保存覆盖。网络或校验失败后，改动内容或点击重试可再次保存；修订冲突和权限失效停止自动重试，避免覆盖其他窗口内容。

`inquiries` 是独立功能权限，管理员可在人员与权限中分配。API 同时检查会话、模块权限、资源所有者和案件归属。即使是管理员，笔录业务内容也按个人隔离；管理员授权能力不会自动获得其他人的笔录。浏览器持久存储仅保存菜单固定偏好，证件、问答和正文保存在服务端。

数据表在 `packages/db/src/schema/inquiries.ts`：

- `inquiry_case`：个人权限容器，`kind=folder` 是案件文件夹，`kind=standalone` 容纳单份独立笔录；保留归档状态、修订号及删除信息。
- `inquiry_record`：所属案件、名称、完整 JSON 正文、草稿/完成状态、修订号及删除信息。
- `inquiry_inquirer`：个人常用询问人，检查证号在个人目录唯一。

列表只读取摘要，笔录每页 30 条，不向列表发送证件号码或完整问答。创建笔录使用客户端请求 ID 去重；更新使用修订号，过期提交返回 409。案件行锁协调归档、删除和笔录写入。

归档案件可查阅和导出，恢复后继续编辑。案件必须先归档才能删除。文件夹内笔录与独立笔录均在树行右侧删除，归档案件内的笔录需先恢复案件。对当前编辑笔录或其文件夹执行删除/归档时，先锁定编辑操作并完成最新修改的保存；保存失败则中止管理操作并保留编辑内容，成功后才离开该编辑器。案件、笔录及常用询问人均标记删除，保留原行、删除时间和操作者。再次添加已删除的同证号常用询问人会恢复原行。没有提供物理清除业务资料的 API。

迁移由 `bun run db:generate` 生成：`20261103162856_inquiries` 新增三张表，`20261103164922_inquiry-deletion-history` 补充删除留痕。两次迁移均已在独立测试 schema 验证并应用到当前配置数据库。新环境运行 `bun run db:migrate` 即可；服务启动不会自动修改数据库结构。

`20261104122310_inquiry-standalone` 在当前库增加 `kind`，旧案件默认仍为 `folder`。`POST /api/inquiries/standalone` 使用同一请求 ID 在事务内原子创建权限容器和笔录，并发重试返回已有笔录；其他人员或资源占用 ID 时拒绝，普通案件新增接口不允许向独立笔录追加内容。目录只返回独立笔录摘要，不返回正文；软删除后不再显示，原有权限、修订号、导出及保存逻辑继续共用。

## 预览、Word 与 PDF

预览复用原项目的 A4 尺寸、仿宋、首续页、签字区和中文页码规则。仿宋资源来自原项目 `apps/api/assets/fonts/仿宋_GB2312.ttf`，置于共享 UI 资源目录。字体加载完成后按实际 DOM 高度测量，逐段二分拆页，按字素边界拆分，保留正文换行；点击文书内容定位对应输入框。

“Word”先保存当前内容，再从后端下载可编辑 DOCX。文件使用已有 PizZip 生成标准 OOXML，文字作 XML 转义，包含动态页码、首续页页眉和签字页脚。Word 使用本机仿宋字体；字体未嵌入，Office/WPS 的换行和页数可能与浏览器预览不同。

“打印 / PDF”在保存后生成同一套实测分页页面，打开浏览器打印预览；选择“另存为 PDF”即可导出 PDF。浏览器打印使用 A4 物理尺寸，不随界面缩放改变。PDF 与 Word 分别适合固定版式和后续编辑，不承诺不同排版引擎逐像素一致。
