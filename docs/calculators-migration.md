## 计算约束

金额以整数分计算，录入最大绝对值999999999999分，累计检查安全整数。原销项、进项、转出可为负，应纳与期末留抵非负；调整分为调增销项、调减销项、调增进项、调减进项，四项均录入非负金额并独立保存；调整后销项 = 原销项 + 调增销项 − 调减销项，调整后进项 = 原进项 + 调增进项 − 调减进项。

首期反推期初留抵：销项 − 进项 + 转出 − 原应纳 + 原期末留抵。每期可抵扣额 = 进项 + 上期留抵 − 转出；应纳=max(销项−可抵扣额,0)，留抵=max(可抵扣额−销项,0)。先用历史留抵核对原申报，再用调整后留抵按实际日期顺序逐期计算。

所属期未完整、相邻所属期断档、负期初或历史普通计税核对不一致会阻断计算；不自动生成任何月份或缺失行。无效调整保留原输入以便继续编辑、保存和备份，但不输出伪完整结果；历史核对链仍独立继续。全部所属期通过后才显示完整合计并允许导出CSV；平衡检查为“应纳净变化 − 最末留抵变化 = 调增销项合计 − 调减销项合计 − 调增进项合计 + 调减进项合计”。年度、联动筛选和网格筛选只影响显示，不改变全期计算与导出。末期仍有留抵差异时提示追加后续所属期。

保留源文件适用口径：一般纳税人普通计税测算，不包含简易计税、减免、加计抵减、出口等特殊事项；应纳差异不直接等同实际补退税。

## 保存与导入

`POST /api/calculators/vat` 使用请求UUID幂等创建。`GET` 列表只读摘要；`GET /:id` 读取完整方案；`PUT /:id` 提交名称、来源、历史、调整与修订号，不能提交客户端计算结果。

保存事务锁定所属方案，旧修订返回409。默认按稳定行 ID 合并原始申报并保留用户行序：相同值跳过，合法的新值更新该行，省略旧行不删除。当前编辑器提交完整方案时显式传 `replaceHistory: true`，以完整 `history` 替换旧申报，支持删行及撤销后的恢复；不得把筛选后的展示行作为完整快照。日期可空，完整日期须有效、起不晚于止且与其他所属期不重叠。同次保存中重复 ID、非法金额和不存在所属期的调整整体拒绝。服务端重算后连同新修订保存。权限不足403，其他所有者/软删除404，坏历史400/422。方案本身仍使用归档管理。

5秒自动保存与手动保存共用串行队列，只确认提交的快照；请求期间继续输入不会被返回值覆盖。离开或切换方案先保存；失败保留输入并可导出备份，刷新/关页有未保存保护。冲突不自动重试覆盖别人版本。

导入支持5MB以内CSV、TSV、TXT、HTML、税务网页XLS；UTF-8失败回退GB18030。二进制Excel要求先另存CSV。HTML用DOMParser读取表格文本，不注入或执行。识别所属期起止、五项金额及原V5别名，排除小规模和汇总行；保留实际日期范围，旧 YYYY-MM 兼容为整月。导入先预览新增/重复/排除和核对问题，确认才合并保存。

JSON导出使用 `vat-periods-v3`（source/history/adjustments/savedAt），恢复兼容旧 `vat-fixed-history-v1/v2`。恢复明确提示替换全部调整、保留额外历史；同期间历史冲突仍拒绝。清空调整也需确认，历史不动。错误通过Sonner，行状态提供说明按钮；表格、弹窗和粘贴区都使用共享ScrollArea。

## 普通税款滞纳金（2026-11-05）

二级菜单新增“滞纳金计算器”，独立路由 `/calculators/late-fees?scenarioId=…`，与增值税计算器共用 `calculators` 模块权限和二级菜单状态。方案选择及串行自动保存抽取为 `ScenarioWorkspace` / `useScenario`，两种业务不共用数据。

支持增值税、企业所得税（年度汇算 / 预缴）、消费税、个人所得税、城市维护建设税、印花税、房产税、城镇土地使用税和其他税款。税种仅标识用途，不自动推定期限。录入确认缴款期限、税款本金、所属期、备注、全方案测算截止日及分次本金缴款；最多50笔税款、每笔50次缴款。

规则核对来源：[税收征管法第三十二条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_1dbea81872cb4fda9ab3ccc45c627531.html)、[实施细则第七十五条、第一百零九条](https://www.chinatax.gov.cn/chinatax/n810214/c102374/c102377/c102378/c3575330/content.html)。普通税款按日万分之五，从最后缴款期限次日起至缴款当日（含）计算；期限的节假日顺延和获准延期由使用者确认。本工具只处理2001年5月1日起的普通税款滞纳金，不代算历史旧费率、特别纳税调整利息、社保费、罚款或减免，不计复利、不自动封顶。

每次缴款当天仍按原欠税余额计费，次日起减少本金；同日多笔不重复计天，期限内缴款不产生滞纳金，结清本金后停止计费。日期转换为 UTC 日序号，避免夏令时偏差。金额输入为整数分，分段乘法和累加使用 BigInt 有理数；每笔税款全部分段汇总后一次四舍五入到分，再汇总方案。明细保留六位小数元的未舍入结果以核对。汇总是累计发生的滞纳金，未扣除已缴滞纳金，不能直接当作尚应缴纳金额。

`late_fee_scenario` 独立保存录入资料、服务端重算快照、规则版本 `tax-late-fee-0.0005-v1`、修订号和所有者。生成并应用追加迁移 `20261105114056_motionless_mattie_franklin`。`/api/calculators/late-fees` 支持幂等创建及摘要列表，`/:id` 支持读取和完整快照保存；所有者过滤、行锁、旧修订409、软删除404与增值税方案一致。未完整/无效数值允许保存原输入，但行结果及全方案合计为空；结构越界422。客户端不能提交权威计算结果。

表单使用 Field、共享 DatePicker、Select、Card、Table/ScrollArea，所有布局尺寸在共享 CSS 的 `late-fee-*` 类中管理。错误经 Sonner 提示；未完成资料不显示红色内联报错或伪零金额。支持多方案、5秒自动保存、切换前保存、刷新保护、JSON导出和单笔移除确认。

## 四项增减调整（2026-11-06）

调整区拆为“销项调整”“进项调整”两个组，每组分别提供调增与调减列。四个原始输入 `outputIncrease`、`outputDecrease`、`inputIncrease`、`inputDecrease` 独立落库；即使同项调增与调减相抵，录入额也完整保留，并仍属于“仅看调整或联动”的调整月份。底部汇总分别累计四列，CSV明细及JSON备份同样保留四项。批量粘贴、撤销重做与自动保存沿用现有网格事务。

旧方案/备份的正销项 `dx` 转为调增销项，负值的绝对值转为调减销项，`di` 转为调增进项，调减进项补零。旧无效输入保留并继续阻断计算，不静默归零；同月混合新旧字段或出现未知金额字段时整体拒绝，避免拼写错误的金额被静默丢弃。读取旧数据库方案只在返回结果中转换并重算，不更新修订号、时间或业务数据；下次用户保存才写入四项格式和v2规则版本。存储继续使用原有JSON字段，不新增数据库表或批量改写方案。

## 原始申报人工修正（2026-11-06）

## 所属期与空行录入（2026-11-06）

每行申报以稳定 `id`、`periodStart`、`periodEnd` 表示，日期与行身份分离；所属期可为季度、非整月或任意连续日期区间。表格以“税款所属期”分组展示两列可编辑日期，复用共享年月日选择器。工具栏“新增一行”直接追加空行；右键单元格可在该行上方/下方插入一行或 1—100 行。先创建空行再选择日期，不推断下个月、不生成虚构申报。插入后清除年度、联动及网格搜索/筛选/排序，定位第一条新行。

空日期、单端日期和零金额可以保存、重读和备份。日期完整后按所属期时间顺序计算，展示仍保持存储行序；未完成期间暂停完整测算和明细导出。日期倒置、无效或重叠会在网格事务及服务端校验时原子拒绝，通过 Sonner 提示，保留旧值。日期批量粘贴、撤销/重做与金额使用同一提交路径。

旧 `month` 在读取时映射到整月起止日期，并保留原月份字符串作为稳定 ID，使原调整键不变化。只读不改写数据库；下次用户保存才写入 v3 所属期格式。沿用原 PostgreSQL JSON 列、权限、归档只读、行锁和 revision，不增加数据库迁移。CSV 分开输出所属期起止，v3 备份恢复保留空行和原顺序。

## 勾选删行与局域网兼容（2026-11-07）

增值税网格启用共享批量删行确认。按稳定行 ID 从完整方案移除申报与对应调整，保留筛选隐藏的其他资料；撤销恢复全表原位置、原始申报和四项调整，重做再次删除。删除后的计算、底部汇总、5 秒自动保存与手动保存共用同一方案快照。删除中间所属期可能形成真实断档，继续按原规则提示计算暂停，不自动补行或伪造完整结果。归档方案禁止删除。
