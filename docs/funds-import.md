# 流水导入、标准模板与字段取舍

创建及维护：2026-10-06。适用于当前 16 文件完整测试案件。字段契约以 `apps/server/src/modules/funds/export.ts` 为准。

## 如何导入

默认流程：资金分析 → 左侧案件菜单选择案件（新案点击菜单顶部加号创建） → 页头“案件管理” → 文件与导入 → 原始文件 · AI 标准化 → 选择原始 Excel/CSV/TSV → 开始标准化并导入。上传完成后可以离开页面，独立 Worker 继续生成标准 CSV、校验、案件归并与图同步。

已有标准模板时切换“已有标准 CSV / Excel”，直接提交。后台处理记录可查看阶段、文件数量、错误/重试、各表映射依据、收支合计及图入库核验；每个文件可下载原件、标准 CSV 和 JSON 转换报告。原件先存入 RustFS 并通过回读哈希校验，再进入后台队列；具体大小和 SHA-256 可在文件核验详情中查看。用户无需维护 Skill 或复制提示词，AI 映射提示词由后端统一版本管理。

当前 16 个原文件均已实际通过 AI 识别映射后转换。AI 只负责理解格式，账号、金额等具体值由程序从原单元格读取；不能确定或不合格内容单列，不猜测补齐。支持 XLSX、XLS、CSV、TSV；PDF/图片/OCR 尚未接入。

模板共 13 列，按用户确认保留查询银行、对方开户行和备注，删除终端号等扩展字段。必需项为本方账号、借贷方向、交易时间、交易金额；其余有原文就保留，缺失时留空，不编造。借表示本方支出，贷表示本方收入。交易时间合并日期和时分秒，格式为 `YYYY-MM-DD HH:mm:ss`，采用银行本地时间 UTC+8。金额固定为人民币元，正数且最多两位小数。负数退款/冲正暂时待核，不能简单改成绝对值。

图节点代表案件内主体：来源中一致的证件标识可关联多个账户；缺少身份依据时，以账户建立持有人待确认主体。户名用于显示和核对，不能仅凭同名归并主体。模板使用本方/对方视角，资金方向由借贷方向决定，交易边仍保留双方账号。摘要与备注独立保存；扩充备注和备注中的有效内容合并到备注列，不因表头精简丢弃。

精简模板不含币种列，系统对这一模板采用 CNY；原始银行表带有币种时仍保留其事实。含外币的资料不能导出成省略币种的精简模板，避免再次导入时误认人民币；既有银行表的分开日期、时间和币种列仍可读取。

账号、卡号、证件号、交易编号按文本填写。按用户要求，Excel 模板仅保留一个工作表和首行字段名，不设置样式、预设数字格式、下拉选项或说明页，与 CSV 使用同一表头。填写或粘贴编号前应将相关列设为文本。CSV 本身没有列类型，通过 Excel“从文本/CSV”打开时也应将编号列设为文本，避免自动数值化。

## 保留哪些字段

| 层次 | 内容 | 用途 |
| --- | --- | --- |
| 账户信息 4 项 | 本方账号、本方户名、对方账号、对方户名 | 识别交易两侧账户；户名不能单独作为身份依据 |
| 交易信息 6 项 | 借贷方向、交易时间、交易金额、账户余额、交易流水号、摘要 | 确定资金方向、排序、汇总、去重与凭证核对 |
| 保留信息 3 项 | 查询银行、对方开户行、备注 | 保留调取机构、对方银行及这笔交易的补充留存信息；查询银行不冒充本方或对方开户行 |

模板与标准流水导出共用上述 13 列，顺序以字段契约为准。原始记录 ID、文件、工作表、行号、SHA256 等来源信息继续由系统保存，通过来源核对入口查询，不混入日常填写模板。全空列、无语义填充符、仅用于原表排序/分页的序号册号笔号、查询任务内部控制字段等不进入标准交易分析。

“查询失败/无明细”等内容分到反馈；开户资料单列统计；负金额、方向或关键时间不明等内容分到待核。它们不能当转账，也不能被视为已清洗掉的无用信息。柜员、凭证日志等暂未规范的字段仍可从原始行核对，不能笼统断言在所有案件中无用。

原文件单独存档是证据溯源职责。分析字段取舍不等于破坏原件，后续增加规则时可以重新解释原始资料。

## RustFS 原件保存（2026-10-06）

原件使用 `funds-originals` 私有桶，路径为 `cases/<案件ID>/originals/<SHA-256>`。文件名、大小、摘要、桶和对象键留在 PostgreSQL，原始文件字节留在 RustFS；标准 CSV、转换报告和规范交易仍保留在关系库。相同案件重复上传相同原件共用一个对象，不同案件使用不同路径。上传和读取均验证 SHA-256；保存失败不创建任务，读取失败停止处理并展示重试提示。

已迁移 16 个来源文件和 32 条历史任务文件记录，全部回读校验；16 个 RustFS 原件与桌面原文件逐一比对一致。迁移没有重跑清洗，资料及图版本仍为 3，规范交易仍为 7,357 笔。

跨案纳入只保存该账户获准范围的 CSV 快照到目标案件，不暴露来源案完整文件；排除后来源下载也不可用。原件下载经过案件权限检查，原始 CSV 编码和 Excel 字节不变。

启动：在 `packages/db` 执行 `docker compose up -d`；RustFS API 为 `http://127.0.0.1:9000`，控制台为 `http://localhost:9001`。开发凭据为 `local-funds` / `local-funds-files-dev`，可用 `apps/server/.env.schema` 中 `RUSTFS_*` 环境变量覆盖。桶在第一次写入时创建，数据保存在 Compose 命名卷。

旧环境先在 `packages/db` 执行 `bun run db:migrate`，然后在 `apps/server` 执行 `bun run files:migrate`。迁移逐件回读校验，成功后才清除旧 Base64，失败可重新运行。备份需要同时包含 PostgreSQL 和 RustFS 数据卷；不配置自动对象过期删除。上传成功但数据库提交失败时可能留下无引用对象，暂不自动清理以免误删原件。
